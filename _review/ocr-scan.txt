PROJECT SUMMARY
### Top Issues

1. **The authentication layer provides no real security boundary, and pages work around it instead of using it.** `auth.js` ships `DEMO_PHONE`/`DEMO_CODE` in the client bundle (readable via View-Source) and `wxAuthorize()` persists a `{ wx: true }` session based only on a `MicroMessenger` UA string check, so `Auth.require()` short-circuits for anyone spoofing the UA. `phone.html` compounds this by re-declaring the demo credentials (violating auth.js's own §演示账号 rule) and writing the private storage key `skl.user` directly to localStorage, bypassing `Auth`. `account.html` has no session guard at all — `Auth.get()` returning `null` silently falls back to `{}` and renders a normal-looking account page with a working logout button. `chat.html` adds a race on top: `Auth.require` is async while the `busy` guard is set later in `doSend`, so concurrent Enter presses queue duplicate callbacks.

2. **String-concatenated `innerHTML` rendering is a trust boundary that is currently only safe by accident.** `chat.html` (`aiBubbleHTML()`), `index.html` (`renderOptions()` rendering `a.src/a.name/a.desc`), and the `el()` helper all build markup from raw strings. Each is described as "only constant demo data today," but any server/model-supplied field becomes XSS. `account.html` has the same shape for `img.src`: `user.avatar` from localStorage is assigned without validation, allowing an external-origin or `data:` URL load.

3. **Timer and state-machine races recur across the app; guards cover the wrong states or are set too late.** `auth.js` `startCountdown()` calls `setInterval` without clearing a prior interval (orphaned timers). `index.html` `recognizeTimer` is nulled but never `clearTimeout`'d, and `isRecording()` returns false during `recognizing` so the mutual-exclusion guard re-opens the UI mid-recognition. `index.html` mode toggle clears the voice branch but leaves `busy`/`sendTimer`. `chat.html` has both a stale `recTimer` overwriting a freshly picked prompt and a TTS `onend`/`onerror` race that cancels the *newly* started utterance. `history.html` `showLoading()` leaks a 900ms timer handle on repeated reload clicks. `phone.html` has no in-flight submit guard, so double-click + Enter duplicates toasts, writes, and redirects.

4. **IME composition is unhandled in the two Chinese-first input surfaces.** `chat.html` and `history.html` both fire on `Enter` without checking `e.isComposing`/`keyCode === 229`, so confirming a 搜狗/讯飞/系统 candidate sends the message or commits a rename.

5. **The error pages fail in exactly the outage they exist to handle.** `404.html` uses `./h5v2/...` and `./index.html` relatively, which resolve against the *requested* nested URL (e.g. `/foo/bar/`), so styles vanish and "回到首页" leads to a second 404. `500.html` depends on externally served `tokens.css`/`base.css`, relies on an inert `<button id="retry">` with no non-JS fallback despite a comment claiming one, dereferences `getElementById('retry')` without a null check, and uses inline `<script>`/`<style>` that a CSP would block.

6. **Persistence and validation are under-specified.** `history.html` re-seeds when `!convs.length`, so a deliberately emptied list is overwritten on reload (delete never persists), and stored items are only `JSON.parse` + `Array`-checked — bad `ts` yields "NaN 个月前" and duplicate ids corrupt delete/rename. `phone.html` copy-pastes phone validation across send/save handlers, and its same-number check plus the DEMO_PHONE check together make the success path unreachable (logic dead-end).

8. **`dev-server.py` has an un-normalized path traversal and inconsistent routing.** `candidate` is built from the raw path with no `..` stripping (rewriting `self.path` to the same un-normalized string), extension resolution lives only in `do_GET` so `HEAD /chat` 404s where `GET` succeeds, and the log filter assumes `args[1]` is always a status code (false for `log_error`).
