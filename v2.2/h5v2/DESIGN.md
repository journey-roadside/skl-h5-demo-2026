# Design — 湖北社科数据信息联盟 · 微信 H5 设计体系 v2

锁定版设计体系。后续所有 H5 页面先读本文件，再写代码；页面之间**共享**这套系统，
而不是各页面各挑一套。`tokens.css` 是令牌唯一真源，`base.css` 是基础层与组件层。
修改请在本文件登记，不做页面级覆写。

> 视觉命名：**靖紫**。一句话主张：**冷雾为纸，靖紫为记，数字人是唯一的活物。**

### 为什么有 v2

v1（`../h5v1/`，代号「荆楚墨印」，已归档）按「索引页 / 长文页 / 事务页」三类骨架建立。
问题不在审美，在**不对口**：H5 的主链路是数字人 AI 对话，而 v1 的组件表里
对话气泡、播报控制、流式生成、限流降级**一个都没有**；它禁止渐变与阴影，
而参考图确立的方向恰恰以这两者为语言。v2 重新建立，v1 保留作对照。

---

## 0 · 系统定位

- **受众** — 社科研究者、高校社科联与重点智库联络人、社科普及工作者、联盟成员单位经办人。
- **场景** — 微信公众号内置浏览器打开，竖屏单手操作，网络条件不确定。
- **任务** — 问得到、读得懂、找得回。三件事：向数字人提问、得到可核查的回答、回到历史对话。
- **语气** — 学术、克制、可核查。不喊口号，不承诺感受，只讲清事实与下一步。
- **与 v1 的分工** — v1 是"机构档案站"的语气，v2 是"机构里的 AI 助手"的语气。
  可以亲近，但不能轻佻：受众是研究者与智库联络人，可信度是硬指标。

## 1 · 系统

- **Genre** · product（对话产品为体，内容为用）
- **Macrostructure** · Companion-First（数字人开场 → 对话流；列表与长文退居次级）
- **Theme** · custom（vibe: "冷雾、靖紫、一点柔光"）
- **Axes** · light / soft-shadow / cool
- **Nav** · 不重绘微信导航；页内只有顶栏（标题 + 形象小头像），底部为输入条

### 1.1 视觉签名（四件，必须出现，不得加第五件）

1. **大圆角白卡 + 柔光阴影** — 20px 圆角的白色平面浮在浅雾底上，深度靠阴影不用线。
2. **品牌渐变** — 只在四个具名位置出现（见 §1.2）。这是"活物"的光。
3. **数字人形象位** — 页面唯一的生命体。随状态缩放是这个体系的性格开关。
4. **合规行** — 对话页底部「内容由 AI 生成，请注意甄别」。不是装饰，是必现项。

### 1.2 渐变的四个合法位置（不得新增第五处）

| 令牌 | 位置 |
| --- | --- |
| `--grad-hero` | 首屏顶部到页面的过渡底色 |
| `--grad-brand` | 用户气泡底、品牌实心按钮底 |
| `--grad-wave` | 语音波形竖条 |
| `--grad-aura` | 数字人形象背后的光晕 |

其他地方一律纯色。渐变是当前 AI 生成物的头号识别特征，无节制使用会让页面廉价；
正文区、数据区、列表区**永不**使用渐变。

## 2 · 令牌

完整表见 `tokens.css`（浅色 + 深色两套）。核心：

```css
:root {
  --canvas:    #F5F4FD;   /* 薰衣草白：页面底 */
  --surface:   #FFFFFF;   /* 卡片底 */
  --mist-1:    #FBFAFE;   /* 卡内嵌套底 / 输入底 */
  --mist-3:    #EDEBFD;   /* 选中底 / 品牌柔光 */
  --ink:       #1E1B33;   /* 主文字 */
  --ink-2:     #4A4666;   /* 次级文字 */
  --ink-3:     #7A76A0;   /* 说明 / 时间 / 合规行 */
  --line:      #E4E2F5;   /* 分隔线 */
  --brand:     #5B54E8;   /* 靖紫 · 品牌信号色 */
  --brand-deep:#443DD6;   /* 按下态 */
  --brand-soft:#EDEBFD;
  --danger:    #D93A34;   /* 危险 · 独立于品牌色 */
  --focus:     #3F37D6;   /* 仅 :focus-visible */
  --r-card:    20px;
  --sh-card:   0 4px 20px rgba(91, 84, 232, 0.10);
}
```

### 2.1 三条用色纪律

**危险色独立于品牌色。** v1 让朱砂一身二职（品牌信号 + 危险），结果是"删除"与"强调"
长得一模一样。v2 拆开：`--danger` 只用于删除、失败、错误。

**阴影一律带品牌色相。** 中性黑阴影在浅紫底上会发脏。所有 `--sh-*` 都用
`rgba(91,84,232,…)`。深色模式改用纯黑加高不透明度（深底上色相看不出来）。

**品牌色可以大面积使用。** v1 规定朱砂任何单屏不超过 5% 面积；v2 取消这条 ——
品牌色是这套体系的主色，不是点缀。但仍受 §1.2 约束：**可以用，不能变成渐变糊。**

### 2.2 兼容性硬约束（v1 的坑，v2 修正）

**禁用 `oklch()` / `color-mix()` 作为唯一的颜色表达。** v1 全站用 `oklch()`，
而该函数需 Chrome 111+；微信 Android 旧内核（X5，微信 8.0.33 以前）不认，
**整条声明会静默失效** —— 颜色没了但控制台不报错，是那种上线才发现、且极难排查的坑。
v2 的颜色一律 `#hex` / `rgba()`。需要混色时在构建期算好写成静态值。

## 3 · 排版

- **比例** — 单一 ≈1.25。**单页最多出现 5 级字号**，其余层级用字重与颜色区分。
- **字号** — 正文 16px 起，永不低于 14px；13px 只给标签、时间与合规行，不承担阅读。
- **行高** — 正文 1.70（汉字字面率高，1.5 会挤）；区块标题 1.34；大标题 1.16（不低于 1.1）。
- **字重** — 正文 400（深色下 350），次级强调 500，标题 600，数据大字 700。
  禁 300 及以下（低分屏上汉字细笔画会糊）。
- **行宽** — 中文长文 `max-width: 34em`（约 26–32 字/行）。
- **对齐** — 一律左对齐。中文窄栏两端对齐会产生字距空洞。
- **标点** — 中文引号「」，顿号、，破折号 ——，省略号 ……。不用英文直引号和 `...`。
- **数字** — 一切数据用 `font-variant-numeric: tabular-nums`，等宽对齐。
- **标题不用斜体**，强调用字重、品牌色或下划线，不用 `<em>` 改字形。

## 4 · 页面骨架

首页与对话页**共用一条数字人状态轴**：形象从"满屏主角"缩为"顶栏小头像"。
这是这套体系的核心决策，见 §4.1 / §4.2。

### 4.1 首页（Companion-Hero）

数字人是主角，占屏约 40%（`--figure-hero`）。首页的职责是建立关系，不是干活。

```
顶部（「切换形象」胶囊，右对齐）
数字人形象位（品牌光晕 + 底部渐隐）
问候语（标题 + 一句说明）
语音波形（收音状态）
底部圆形操作区（录音 · 键盘）
```

节奏：**疏**。首屏不超过 4 个信息块，留白是设计的一部分。

### 4.2 对话页（Companion-Chat）

**同一个数字人缩为顶栏 44px 圆头像**，把屏幕全部让给对话流。
一屏一主：首页形象说话，对话页内容说话。

```
顶栏（44px 形象小头像 + 会话标题 + 「新建对话」图标钮 + 「历史」胶囊）
欢迎卡（仅在无对话时出现：左文案 + 右形象 + 整宽提示词位）
对话流（气泡：用户右侧渐变 / AI 左侧白卡）
底部输入条（两态：键盘 / 录音 —— 见 §5.1）
AI 标识合规行（输入条下方）
```

欢迎卡形态取自参考图 CueMe 对话页：对话尚未开始时，用一张横向卡把
"我是谁、能做什么、从哪里开始"一次说清，而不是留一片空白等用户输入。
一旦有了第一条消息，欢迎卡让位给对话流。

**卡内形象靠右上，头顶越出卡片上沿（出血），且绝对定位、脱离正常流。**
旧版是「靠右下 + 底部出血」，读起来像形象从卡片下缘长出来；
新版是形象探出卡片、望向正文，头就必须在卡片之上。

**为什么必须脱离流**：它曾在流里且高 150px，整行高度被它撑到 150；
而文案块在桌面上只有 56px（标题一行），于是缩下来的是「标题与提示词之间
空出 66px」，窄屏则是它吃掉 120px 宽度、文字列只剩 108px、标题折五行。
**两个症状同一个病根**。改成绝对定位后行高只由文案决定，
空隙恒为一级 gap（16px），也不必按分辨率分档调尺寸。

代价是它不再占位，**文字让位必须由 `.herocard__body` 的 `padding-right`
显式给**，宽度取 `--herocard-figure-w`（该变量在 `:root` 上定义，
是组件几何不是设计令牌，故留在组件层）。

尺寸随屏宽连续缩放：`clamp(68px, 22vw, 116px)`。系数取 22vw 而非 25vw ——
320px 视口下 25vw 算出 80px，触碰不到下限，窄屏等于没缩。

**上出血量写 `top: -20px`**：绝对定位的 `top` 相对的是包含块的内边距盒
（此处即卡片上沿），所以直接是「越出卡片 20px」。注意这不是负 margin 时代的
`-(padding + 越出)` 算法，改写法时别照搬旧数值。

**下缘渐隐：同一种手法，两条不同曲线。** 首页与卡内形象都用
「底部线性遮罩把下缘化开」，避免生硬截断，但区间不同 ——
首页 `58% → 94%`（给占屏 40% 的大形象），卡内 `70% → 100%`
（形象只有 90px 上下，照搬会把大半个身子抹掉）。**别互相照抄。**

出血带来两条连带约束，改这里时都要顾到：
1. **卡片不能裁剪**。不能用 `overflow: hidden`，更不能用 `clip-path: inset(0 …)`
   —— 后者四边一起裁，头顶照样被切。原由 hidden 顺手兜住的两件事各有其主了：
   渐变块自己 `border-radius: inherit`，提示词轮播自己 `overflow: hidden`。
2. **上方必须留出空间**。卡片离 sticky 顶栏的默认间距只有 16px，不够；
   页面要给足一档（见 `chat.html` 的 `.herocard { margin-top: var(--sp-lg) }`），
   否则头顶被顶栏盖住。

**「从哪开始」用提示词位，不用按钮。** 按钮只说了「可以问」，提示词直接给出
「可以问什么」，还省掉一次点击。它是**单行窗口 + 逐条滑出滑入**，
一次只给一条 —— 摊开三条反而要先挑，又变成选择题。点击只把文字**填进输入框**
不直接发送：用户常想改一两个字再问，发出去就收不回来了。

落地时注意宽度：提示词位必须占**整卡宽度**（`.herocard__wide`），
挤在 `.herocard__body` 里会被右侧形象分走一半（375 视口下只剩 163px），
一条完整的提示词放不下。

**已移除快捷提问 chips。** 空态由欢迎卡的「开始提问」一个入口引导即可，
再加一排 chips 等于在同一屏给两个并列的起点，用户要先选「用哪个方式开始」——
那不是他此刻想的事。

**AI 标识放输入条下方**，不是上方：它是输入区的注脚（「你输入的内容会怎样被回答」），
贴着输入条才好读；夹在对话流与输入条之间会被读成对话流的一部分。
落地时注意输入条已不是页脚最底元素 —— 它的 `--pad-bottom` 要移交给 AI 标识，
否则会在两者之间留一段谁也解释不清的空隙。

节奏：**密**。气泡间距 16px，长回答的正文行高 1.70。
**不用"固定高度 + 内层滚动"** —— 那需要写死高度，违反官方"避免绝对高度"（§9）。
正确做法：整页滚动，顶栏与输入条 `position: sticky`。

宽度比其余页面宽一档（`--w-docpage` 1000px，见 §9 第 13 条）：
对话是持续阅读场景，PC 上按 640px 收窄会让气泡与输入条挤成一条窄栏。

### 4.3 列表页（历史对话）

```
页头（标题 + 一句话说明 + 右侧返回钮）
行列表（会话标题两行截断 + 相对时间 + 消息数 + 编辑 / 删除图标）
编辑名称、删除各走一次 sheet 确认
```

节奏：**密**。行高 44px 起，行间 1px 次分隔线。

**不放吸底「新建对话」按钮。** 页头有返回、对话页顶栏有「新建对话」，
本页再加一个就是同一条路径上的第三个入口 —— 动作重复不会让人更快，
只会让每屏都多一块常驻按钮。

**返回钮靠页头最右**，与标题同行。它是**二级页**：
来源由跳转方用 `?from=` 带上（`chat` / `index`），本页只读不写；
取值走白名单，未知来源按层级回首页。不用 `history.back()` —— 直开
（收藏 / 分享）时栈里没有上一页，`back()` 毫无反应。

### 4.4 状态页（非微信引导 / 授权 / 失败重试）

```
居中的一句话说明
一个明确的动作按钮
可选：二维码或图形
```

节奏：**居中、单点**。这类页面只做一件事，不要加导航、不要加推荐。

## 5 · 组件

`base.css` 已实现。命名与用途：

| 组件 | 类名 | 用途 | 关键约束 |
| --- | --- | --- | --- |
| 页面容器 | `.h5` `.h5__main` | 页面骨架 | `min-height: 100dvh`，上限 `--w-content` 640px 居中 |
| 对话页骨架 | `.docpage` `.docpage__bar` `.docpage__flow` `.docpage__foot` | 对话页 | 顶栏与输入条 sticky，**不写死高度**；上限 `--w-docpage` 1000px 居中 |
| 数字人形象位 | `.figure` `.figure__img` | 首页主角 | `.figure` 带底部渐隐（58%→94%）；`.figure__img` **不再有遮罩与混合模式**（素材已是透明底） |
| 形象小头像 | `.figure--dock` | 对话页顶栏 | 44px 圆头像 |
| 对话页欢迎卡 | `.herocard` `.herocard__wide` | 对话页空态 | 左文案 + **右上形象（头顶出血到卡外、下缘渐隐）** + 整宽行；有首条消息后让位给对话流。滚播级不可裁剪（形象要出血）；渐变块自己 `border-radius: inherit`。`__body` 用 `flex:1 1 0` 只吃剩余宽 |
| 问候语 | `.greet` | 首页 | 压在形象渐隐处仍须可读 |
| AI 标识 | `.aiflag` | 对话页 | **必现，不可省** |
| 气泡 | `.bubble--user` `.bubble--ai` | 对话流 | 用户渐变右 / AI 白卡左，最大 `min(84%, --measure)`——PC 加宽后靠行宽令牌兜住 |
| 来源标注 | `.bubble__src` | AI 回答 | 回答须可核查，连带出处 |
| 生成中 | `.bubble--typing` | 流式等待 | 三点，不是转圈 |
| 语音波形 | `.wave` `.is-live` | 播报 / 收音 | 静止态不空转，只在真播报时动 |
| 输入条（两态） | `.composer` `.composer__mode` `.composer__field` `.composer__rec` | 对话页 | sticky 吸底 + 安全区；左键切模式，右侧随模式换形态。状态机见 §5.1 |
| 圆形操作钮 | `.iconbtn` `.iconbtn--sm` | 录音 / 键盘；`--sm` 给页头图标动作 | `--sm` 取 `--h-pill` 36px，与同排的 `.pill` 同高；输入条左侧的 `.composer__mode` 取 `--h-control` 与输入框对齐 |
| 快捷提问 | `.chips` `.chip` | 首页 / 对话 | 短标签不折行，长度受 §3 约束 |
| 卡片 | `.card` `.card__inset` | 内容块 | 卡中卡允许，但内层须降级为无阴影浅底 |
| 行列表 | `.rowlist` `.row` | 历史对话 | 行高 44px 起 |
| 按钮 | `.btn` + 变体 | 操作 | 高 44px，六态齐备 |
| 胶囊 | `.pill` | 顶栏次级动作 | 高 `--h-pill` 36px；页面需更矮时用变体类覆写，不改组件 |
| 标签 | `.tag` | 分类 / 状态 | 高 24px，不换行 |
| 空态 | `.empty` | 无数据 | 三句式文案 + 一个按钮 |
| 骨架 | `.skeleton` | 加载 | 降级为静态 70% 不透明度 |
| 反馈条 | `.toast` | 结果不可见时 | **可见结果不给提示条**；统一**走顶部**，底部永远有吸底动作区 |
| 弹层（底部） | `dialog.sheet` | 就地确认 / 快选 | 原生 `<dialog>`；从底部升起，视线不离开当前内容 |
| 弹层（居中） | `dialog.modal` | 需专心完成的表单（如登录） | 原生 `<dialog>`；屏幕居中、四角圆、`position: relative`。与 `.sheet` 只差位置与圆角，共用同一套背板 / 阴影令牌。**弹层内的反馈条要挂在 dialog 内部**——`.toast` 本身不动（仍 `position: fixed`，与页面级同一位置），只因 `::backdrop` 在 top layer 而必须如此 |
| 表单 | `.field` `.field__input` | 输入 | 字号 16px；错误容器不塌陷 |

**组件状态基线**：交互元素至少实现 default / hover / focus-visible / active /
disabled 五态。输入框另加 error。状态切换只改 `background-color`、
`border-color`、`outline-color`、`transform`，**不改 border-width**（会抖）。

**焦点环**：`outline: 2px solid var(--focus)`，`outline-offset: 1px`，
静态出现，永不淡入。

### 5.1 输入条 · 两态三步骤

左侧按钮切模式，右侧随之换形态。四个状态：

```
键盘态 ──点左侧──▶ 录音待开始 ──点右侧──▶ 录音中 ──点右侧──▶ 识别中 ──▶ 键盘态
   ▲                                                              │
   └──────────────────────点左侧（随时可切回）─────────────────────┘
```

| 状态 | 左钮图标 | 右侧 | 文案 | 无障碍 |
| --- | --- | --- | --- | --- |
| 键盘态 | 麦克风 | 输入框 | placeholder | 左钮 `aria-label="切换到语音录入"` |
| 录音待开始 | 键盘 | 按钮 · `--brand-soft` 底 | 点击开始录音 | 左钮 `aria-label="切换到键盘输入"`，右钮 `aria-pressed="false"` |
| 录音中 | 键盘 | 按钮 · `--brand` 实心底 + `--on-brand` 字 | 点击结束录音 | `aria-pressed="true"` |
| 识别中 | 键盘 | 按钮 · 半透明禁用 | 正在识别… | `aria-busy="true"` + `disabled` |

四条实现纪律：

1. **图标表「按下去会得到什么」（下一步动作），不是「当前模式」。**
   键盘态显示麦克风、录音态显示键盘。显示当前模式在纸面上也说得通，
   但会造成实际困惑：输入条里摆个键盘图标，用户以为「点它是唤起键盘」，
   而它其实会把输入框收走切到录音。图标与 `aria-label` 因此表达同一件事。
2. **两个图标都写在 DOM 里，由 CSS 切 `display`**，不用 JS 换 SVG。
   切换模式时输入框只是 `display:none` —— **已输入的文字与焦点都不丢**，
   回到键盘态再把焦点送回输入框。
3. **识别中必须有中间态**。转文字不是瞬时的，点完结束立刻回键盘态，
   用户会以为没录上。按「不加波形、不加计时」的约束，只换文案 `正在识别…`
   并禁用按钮，防重复提交。
4. **切模式时把录音态收干净**，并 `clearTimeout` 掉在途的识别定时器 ——
   否则迟到的识别结果会写进已经切走的输入框。

**状态不只靠颜色**：录音中用底色 + 文案两重表达，不单靠色相变化（§10）。

**不设发送钮**：键盘态靠 `enterkeyhint="send"` 用系统键盘的「发送」提交，
与微信一致。输入条因此恒为两段，320px 才放得下。

**演示与真实 ASR**：`chat.html` 里的 `RECOGNIZED` / `RECOGNIZE_MS` 两个常量
即模拟层，接真实接口时替换这两处，状态机不动。

## 6 · 数字人形象

形象是本体系最强的资产，也是最容易失控的地方。三条规矩：

**首页形象位与对话页形象位是两个东西，不要混。** 首页 `.figure` 高
`--figure-hero`（286px，约占 375×812 屏的 35%），是页面的主角；
对话页用 `.figure--dock`（44px 圆头像）挂在顶栏，把屏幕让给内容。
参考图里有形象占屏 60% 的做法，那适合"形象即产品"的场景；
本产品首页需要品牌感、对话页需要信息密度，两者用尺寸区分职责。

**素材须透明底，且现已如此。** 当前占位素材（`assets/avatars/`）四角
`alpha = 0`，是真正的透明底 PNG（可用 canvas 取 `(0,0)` 像素验证）。
所以 `.figure__img` 上**不再有** `mask-image` / `mix-blend-mode` ——
那两条是为白底抠图写的「融白底」手段，素材换透明底后只剩副作用：
径向遮罩的纵向实心区只覆盖 20%~80%，而 1:1 素材的人物从第 0 行就开始，
头顶整段落进渐隐区被压掉（**2026-10-11 实际发生过，已修**）。

**以后换素材时先验底色再决定要不要遮罩**，别照抄旧规则。
`.figure` 自身的底部线性渐隐（与下方文字重叠时压得住）是另一回事，保留。

**形象未授权前不进生产。** 形象授权是 PRD 遗留项。占位素材仅用于原型演示，
不得随演示站公开分发。字号在形象位内不随档位放大，这属于官方允许的
"固定几何控件"豁免（§9.1）。

## 7 · 文案

- **按钮写动词**：「开始提问」「新建对话」「查看全部 47 条」。不写「确定」「提交」「点击这里」。
- **链接能独立看懂**：「查看全部 128 条数据资源」，不写「更多」。
- **空态三句**：① 空的是什么 ② 为什么会有它 ③ 一个按钮。
  例：「还没有对话记录。你提过的问题会保存在这里。」+「开始提问」
- **报错三句**：① 出了什么事 ② 为什么 ③ 怎么办。
  例：「没能连上服务。当前网络不稳定。请检查网络后重试。」
- **限流文案统一**：「当前使用人数较多，请稍后再试」。**不暴露内部阈值。**
- **加载**：短等待只转圈；超 2 秒加「加载中…」；超 10 秒给进度与诚实说明。
- **AI 回答必须可核查**：涉及数据与成果时连带来源（`.bubble__src`），
  没有出处就不给具体数字。**不编数字**，没有真实数据就写「—」。
- **禁用词**：「赋能」「打通」「一站式」「智慧 XX」「一键解锁」「开启新篇章」
  「我们致力于」「值得信赖」——这些词删掉不影响信息量，就不该出现。

## 8 · 动效

- 只动 `transform` 与 `opacity`。绝不位移宽度、高度、margin、padding。
- 三条命名缓动之外不使用浏览器默认 `ease`，不用回弹、弹性、过冲。
- 三条时长：`--dur-micro` 按下反馈、`--dur-short` 开合、`--dur-long` 弹层。
- 允许的动效仅五种：按钮按下 `translateY(1px)`、语音波形呼吸、
  生成中三点、背景色/边框色过渡、弹层透明度 + 缩放（0.98 → 1）。
- **波形只在真正播报或收音时动**（`.wave.is-live`）。静止态停住 ——
  无限空转的装饰性动效是 AI 生成物的另一个识别特征。
- **禁止**：滚动视差、元素入场逐条淡入、自动轮播、光标跟随、
  加载光条循环扫过。
- `prefers-reduced-motion: reduce` 下全部时长压到 150ms，波形与骨架停住保形。

## 9 · 微信 H5 工程约束

这一节与视觉无关，v2 从 v1 整套继承 —— 这些是踩过的坑，没有理由推翻。

1. **视口标签**必须写全：
   `<meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">`
2. **安全区**用 `env(safe-area-inset-*)`，`tokens.css` 已封装成
   `--safe-top/--safe-bottom/--safe-left/--safe-right`，页面直接用变量。
   底部固定条必须自加 `var(--pad-bottom)` 内边距，否则会被小黑条盖住。
3. **不重绘微信导航**。顶部标题栏与返回键由容器提供，页面内只做自己的顶栏与输入条；
   不自绘返回箭头、不画胶囊按钮、不画浏览器外壳。
4. **不下载中文 Web 字体**。全量 CJK 字库普遍 5MB 以上，微信内加载会导致首屏白字。
   本体系中文使用系统字族；若需 Archivo 的数字与拉丁外形，**必须自托管拉丁子集**
   （≤40KB woff2，`font-display: swap`）放入 `fonts/`，否则自然回落到系统字。
   **禁止**引用 `fonts.googleapis.com`：中国大陆不可达。
5. **默认路径不写 `text-size-adjust` 的禁用值**，让微信的字体档位真的放大文字。
6. **高度用 `dvh` 不用 `vh`**，微信地址栏收放会导致 `100vh` 跳变。
7. **不用 `100vw`**，用 `100%` 加内边距。
8. **`gap` 兼容**：微信 Android 旧内核（X5，微信 8.0.33 以前）对 flex `gap`
   支持不完整。若需覆盖旧版本，把 flex 容器的 `gap` 换成 `margin-inline-end`
   相邻选择器。2023 年后的微信版本无需处理。
9. **iOS 微信底部返回栏**：页面有 history 时 iOS 会多出一条前进/后退栏，
   可能遮挡底部弹层。更稳的做法是**把关键操作抬离屏幕最底部 80px 以上**，
   本体系用 `--pad-bottom` 兜底；必要时把 `--inset-toolbar` 调成该栏高度。
10. **不自动播放音视频**，不在首屏请求摄像头/麦克风/定位权限。
    **数字人播报须由用户手势触发**，不自动出声。
11. **不诱导分享**，不弹全屏遮罩，不遮挡返回键。
12. **图片**必须带 `width`/`height` 防抖动，首屏图不 `lazy`，其余 `loading="lazy"`。
    形象图用 WebP，单张控制在 200KB 内。
13. **页面容器**统一居中，平板与横屏下不铺满全宽。上限按内容类型分两档：
    `.h5`（列表页 / 状态页）用 `--w-content` 640px；
    `.docpage`（对话页）用 `--w-docpage` 1000px —— 对话是持续阅读的长文场景，
    640px 在 PC 上会把气泡与输入条挤成一条窄栏。手机上两者都占满宽度。

### 9.1 微信大字体（适老化）适配

依据微信支付官方《商户收银台 H5 大字号规范 · 通用规则》
（`pay.weixin.qq.com/doc/v2/partner/4011937062`，2025-03-21 版）第 4 节：
元素随档位缩放、**间距不跟随缩放**（用绝对单位）、**避免绝对高度**、
**避免 100% 高度**、文字 ≥40dp 可不参与放大。

本体系的单位分工按这几条设计：

| 规则 | 做法 |
| --- | --- |
| 文字随档位放大 | 字号用 `rem`，且不设置禁用 `text-size-adjust` |
| 间距不跟着变形 | 间距、点击热区、圆角、固定几何用 `px` |
| 避免高度写死 | 含文字的容器用 `min-block-size` + 内边距，不用 `height` |
| 页面必须能滚 | `.h5` 用 `min-height: 100dvh`，全站无 `height: 100%` |
| 允许文字换行 | 正文与元信息不设 `nowrap`；只短控件标签 `nowrap` |
| 内容不被遮挡 | 底部条用 `sticky` + 安全区内边距，不用 `absolute` 覆盖内容 |
| 键盘不挡输入 | 输入框带 `scroll-margin-block` |
| 拥挤时容器随文字长高 | 行、按钮、标签栏一律 `align-items: center` |

**唯一允许写死尺寸的场景**：固定几何控件（开关、进度条、数字人形象位）、
圆形操作钮、≤3 字的导航标签。写死的位置在代码里留一行注释说明原因。

**长度约束（配合 `nowrap` 使用）**：按钮与页签标签 ≤8 个汉字；
底部标签栏标签 ≤3 个汉字。超长就换短词，不要截断，也不要让它折成两行。

**实测档位**：交付前需在微信「设置 → 通用 → 字体大小」调到第 6 档与最大档各看一次，
重点看四处 —— 顶部栏（形象头像 + 标题）、快捷提问 chips、底部输入条、气泡。
溢出时优先缩短文案，其次减少同一行元素数量，最后才考虑把该元素字号写死为 px。

**放大机制**：iOS 走 `-webkit-text-size-adjust` 渲染层等比放大；
Android 走 WebView 文字缩放（等价 `setTextZoom`）。两条路径都不使用
`user-scalable=no` 去锁字号 —— 它只禁双指缩放，对微信档位无效，
还会在部分机型上让 `position: fixed` 与输入框聚焦出错。

**上线验收（官方第 5 节要求）**：必须在 **iOS 与 Android 各做一次真机验收**，
覆盖最小机型（iPhone SE、安卓小屏机）。官方三条自查项：
① 文字、图片、按钮均放大；② 无溢出、遮挡、重叠；
③ **字体调到第 6 档时，页面主要文字不小于 18dp/pt。**
默认路径下由微信放大倍率满足（16px × ≥1.1 已过 18）。

## 10 · 无障碍

- 对比度：正文 ≥ 4.5:1，大字 ≥ 3:1，图标与焦点环 ≥ 3:1。
- 语义结构：`<h1>` → `<h2>` → `<h3>` 不跳级；列表用 `<ul>`/`<ol>`。
- 装饰性图形 `aria-hidden="true"`；承载信息的 SVG 必须 `aria-label`。
- **状态不只靠颜色**：通过/失败/待办必须带图标或文字；
  品牌色与危险色已分离（§2.1）但仍须双通道。
- 表单：`label` 与控件显式关联；必填加 `required` 与视觉星号；
  错误用 `aria-describedby` 指向帮助文字；错误容器不塌陷（`min-height: 1lh`）。
- 触控热区 ≥ 44×44px，元素之间 ≥ 8px，避免误触。
- 不用 emoji 充当信息图标。
- **音频与播报必须可关闭**，且提供文字替代（波形旁给状态文字，不只给图形）。

## 11 · 禁止项

出现任意一条即为不合格，改掉再交付。

**色彩与图形**：`oklch()` / `color-mix()` 作为唯一颜色表达（X5 不认）；
纯 `#000`/`#fff` 作大面积底；紫蓝渐变用作**背景糊**而非 §1.2 的四个位置；
渐变文字；玻璃拟态；光晕滥用；彩色投影；厚色条左边框卡片；
三列等宽图标卡；装饰性无意义图形；超过 4 处渐变。

**排版**：标题斜体；标题字重 300 及以下；正文小于 14px；超过三种字体族；
全大写英文段落；中英混排不加空格；用 `...` 代替 `……`。

**交互**：`transition: all`；统一 `hover: scale`；回弹缓动；焦点环淡入；
只用颜色表达状态；仅 hover 可用的操作；点击文字换行成两行；
自动轮播且不可暂停；无限空转的装饰性动效；成功提示条（结果已可见时）；
数字人自动播报出声。

**工程**：`100vw`；`overflow-x: hidden` 作为横向溢出的兜底；
第二个 `top: 0` 吸顶元素；`z-index: 9999`；Google Fonts 外链；
未自托管的 CJK Web 字体；缺 `alt` 的图片；`<div>` 冒充按钮；
对话页缺少 AI 标识；形象素材未授权即进生产。

## 12 · 页面怎么装配

```html
<!doctype html>
<html lang="zh-CN">
<head>
  <meta charset="utf-8">
  <meta name="viewport" content="width=device-width, initial-scale=1, viewport-fit=cover">
  <title>页面标题 | 湖北社科数据信息联盟</title>
  <!-- 路径按你的项目结构改写：指向这套设计体系文件的实际位置 -->
  <link rel="stylesheet" href="./h5v2/tokens.css">
  <link rel="stylesheet" href="./h5v2/base.css">
</head>
<body>
  <div class="h5">
    <main class="h5__main">
      <!-- .card / .herocard / .bubble / .composer … -->
    </main>
  </div>
</body>
</html>
```

规则：

- 业务页面**只写结构与组件类名**，不新增颜色、字号、间距的裸值。
- 需要新数值时，先提升为 `tokens.css` 里的具名令牌，再引用。
- 不覆写 `base.css` 里的组件样式；用变体类（`.card--pad-sm`）扩展。
- 一次改动的范围要能在一个页面文件里说清；跨页面的改动写回本文件。

## 13 · 决策记录（为什么是这样）

| 决策 | 理由 |
| --- | --- |
| 新建 v2 而非改 v1 | v1 骨架（索引/长文/事务）与主链路（对话）不对口，改等于重写；保留 v1 可对照 |
| 主色选明亮靖紫 `#5B54E8` | 在 A/B 实物对比后选定。B（黛青紫）更稳但偏沉，A 更贴近参考图确立的方向 |
| 数字人随状态缩放 | 首页与对话页若都用大形象会打架；缩为顶栏头像后，一屏一主 |
| 首页大形象 / 对话页小头像 | 首页要品牌感、对话页要信息密度；尺寸区分职责，一屏一主 |
| 危险色独立于品牌色 | 修掉 v1「朱砂一身二职」导致删除与强调同形的问题 |
| 渐变限定四处 | 渐变是 AI 生成物头号识别特征；无节制使用廉价化 |
| 颜色弃用 `oklch()` | X5 内核不认，整条声明静默失效，属上线才暴露的坑 |
| 对话页整页滚动 + sticky | 官方要求"避免绝对高度"；固定高度内层滚动需写死高度 |
| 保留 AI 标识为必现项 | 合规要求，也是"可核查"语气的落点 |
| 继承 v1 全部工程约束 | 视口/安全区/字体/单位分工与视觉无关，是踩过的坑 |
| 输入条用两态而非三段式 | 三段式（录音钮 + 输入框 + 发送）三个控件并列，320px 放不下，且模式切换要跨控件跳跃；两态一钮切模式，恒为两段 |
| 不设可见发送钮 | 与微信一致：系统键盘的「发送」即提交。省一个 44px 控件，输入条才放得下两段 |
| 左钮图标指「当前模式」而非「下一步动作」 | 图标是状态指示，动作交给 `aria-label`。否则图标与 `aria-label` 打架，读屏用户无法判断按下去会发生什么 |
| 加「识别中」中间态 | 转文字非瞬时。点完结束立刻回键盘态，用户会以为没录上，进而重复录音 |
| 录音结束后转文字填框、不直接发送 | 语音识别有误差，直接发送等于替用户做决定；填框后可改可删，控制权留在用户手里 |
| 录音中只换文案、不加波形计时 | 演示站要"任何机器都能演"，波形与计时会让人误以为真在采集；也避免与 §1.1 的 `--wave` 播报态混淆 |

**参考图里明确不照抄的三点**：① 形象占屏 60%（改 35%）；② 品牌色兼任危险色
（改独立）；③ 无节制的渐变与光晕（改限定四处）。
